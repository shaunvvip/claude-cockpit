# v0.5.1-beta — statusline data fixes (5 root causes)

Right after v0.5.0 shipped, all statusline data fields stayed at `0` in active sessions. Five overlapping bugs:

| Bug | Symptom | Fix |
|---|---|---|
| **A** TranscriptWatcher started tailing from EOF | Daemon started mid-session → all prior tool calls / USAGE / TODOS dropped | `offset = 0` + drain on start, all history flows in |
| **B** `ctxPct` only used `input_tokens` (per-turn delta) | input is usually <100 even at 30k context fill → always showed 0% | Sum `input + cache_read + cache_creation` |
| **C** `cost` never stored on `SessionState` | Field always `$0.00` | Extract `cost.total_cost_usd` from Claude Code stdin, forward through `UPDATE_SESSION` |
| **D** `TODOS` event in union but never emitted | Detail-page TodosPanel always empty | Parse `TodoWrite` tool_use input.todos in `TranscriptWatcher.handleLine` |
| **E** statusline never sent `pid`/`ppid` to daemon | `[stop]` always returned 422 "no ppid" | Include `process.pid`/`process.ppid` in `UPDATE_SESSION` payload |

Also added `cacheCreationTokens` to USAGE event + SessionState for completeness.

**Tests:** +4 (drain-from-zero, TODOS, cache_creation in USAGE, cost in stdin). 177 / 177 total pass.
