# v0.5.3-beta — ANSI-colored statusline bars + layout polish

The statusline was rendering `[████░░░░░░]` in plain text — at 95% context it looked the same as at 5%. Brought the visual hierarchy up to claude-hud parity.

## Color thresholds

| Bar | <green-zone> | <yellow-zone> | <red-zone> |
|---|---|---|---|
| ctx (window usage) | green <70% | yellow 70-84% | red ≥85% |
| 5h / 7d (quota) | bright-blue <75% | bright-magenta 75-89% | red ≥90% |
| empty cells | `DIM` (visually subordinated to the colored fill) | | |

ANSI 8-bit codes only — works in iTerm2, Ghostty, WezTerm, Kitty, VS Code, Warp without truecolor support.

## Layout polish (3 typographic moves)

1. **ctx now renders bar-before-percent** like 5h/7d. All three gauges share visual rhythm.
2. **Line 2 separator** changed from ` · ` to `    ` (4 spaces). Colored bars are already heavy; dots became noise.
3. **Countdowns are DIM** — `(3h 31m)` reads as secondary annotation, not competing with the percent.

## Also in this release

- **`detached` placeholder dropped** — when stdin's `workspace.current_branch` is absent the segment is simply omitted. The old label was misleading outside git repos.
- **Layout swap** — Line 1 = `model · cwd · branch? · tools N↑ · todos a/b · [dash] [stop] [file]` (identity + work + actions). Line 2 = all three gauges. Operations and gauges no longer interleave.
- **Cost dropped from statusline render** — 5h/7d bars give more useful context than a raw dollar amount. Cost remains stored on `SessionState` and shown on the dashboard.
