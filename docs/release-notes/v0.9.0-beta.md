# v0.9.0-beta — SQLite history layer

The big graduation. Cockpit's data is no longer in-memory only — every session, tool call, alert, and 5h/7d snapshot is durably persisted to a local SQLite database. The new `/history` page surfaces 30-day trends, top-N projects/tools, and per-project totals.

## Highlights

- **History layer** — `~/.claude-cockpit/cockpit.db` (better-sqlite3 WAL). 5s batched flush; 90-day rolling cleanup at local midnight; daily catch-up if the daemon was offline across a boundary.
- **`/history` page** with three tabs:
  - **Trends** — 30-day daily cost bar + cache hit rate line + 5h/7d subscriber-usage history
  - **Top** — `metric × dimension` matrix (cost / tokens / tool-calls × project / tool / session)
  - **Projects** — per-project totals (cost / sessions / tokens / last activity) grouped by `workspace.project_dir`
- **Overview Sparklines** are now backed by real 24-hour aggregates — `mockCost24` and `mockCtx24` are gone.
- **`cost-spike` baseline migration** — from in-memory rolling (recomputed on every daemon restart, only counts sessions ≥ 30min) to SQLite 7-day window. Far more stable; the 30-min noise gate is gone.

## What's under the hood

- 4 tables (sessions / tool_calls / events / usage_snapshots) + schema_meta version table for future migrations
- `HistoryStore` class — in-memory queues drained transactionally on 5s flush; `INSERT OR REPLACE` for sessions, `INSERT OR IGNORE` for tool_calls (idempotent re-ingest after daemon restart), value-change dedup for usage_snapshots
- 6 new GET endpoints under `/api/history/*` + `POST /api/history/clear` with Origin guard (R21)
- Hourly DB size monitor — warns over 500MB
- Graceful degradation if `better-sqlite3` fails to load — daemon stays alive, `/history` shows friendly fallback, `cost-spike` reverts to v0.5 behavior

## Backup + clear

~~~bash
# Back up
cp ~/.claude-cockpit/cockpit.db* /your/backup/dir/

# Clear via API
curl -X POST http://localhost:<port>/api/history/clear

# Or via dashboard: Projects tab → "Clear all history…" with confirm modal
~~~

## Configuration

`~/.claude-cockpit/config.json`:

~~~jsonc
{
  "retentionDays": 90,
  "historyFlushMs": 5000
}
~~~

## Known limitations

- `tool_calls.duration_ms` is not yet recorded (would require pairing tool_use with tool_result — deferred to v0.9.x patch)
- `/alerts/feed` page not yet built (the underlying events table now persists alerts; UI deferred to v1.0 or later)
- macOS notification deep-link click is still limited by `osascript display notification` API — same as v0.5
